# T-007/chunking — level + selected-car geometry chunks

**Date:** 8 November 2026
**Scope:** split the 15-car `_work/e1-drive/geometry.json` (106,864,802 B) into a
level chunk, one chunk per roster car and an index; load the level once and only
the selected car (plus the MP peer car); keep every packet anchor, ghost and
per-car behaviour. Design: `docs/plan/VEHICLE_CHUNKING.md`.

## 1. Chunk schema and files

`probes/e1-drive/tools/build_geometry.mjs` is now a chunk writer. The packet
schema is unchanged: the loader merges exactly one car body into the level
document, so `web/packet-adapter.js` still receives `geometry.carBodies[slug]`
and the same `geometry.version === 6` document it received before.

```
_work/e1-drive/
  level.geometry.json       9,662,959 B   always loaded
  base.geometry.json           10,778 B   map-package base only
  car-bodies.index.json        16,858 B   SHA-256 / bytes / draws / texture+UV refs
  cars/<slug>.geometry.json  5.47–9.02 MB one car body (selected on demand)
  geometry.json             106,864,802 B combined debug artifact (never fetched)
```

Kinds/versions:

- `level.geometry.json` — `kind: "e1-drive.geometry"`, `version: 6`,
  `chunk: {kind:"level", version:1}`, `carBodies: {}`, two static meshes
  (level props + track visual), 22 level draws, 394 track draws, collision
  surface hidden.
- `base.geometry.json` — `kind: "e1-drive.geometry"`, `version: 6`,
  `chunk: {kind:"base", version:1}`; materials, light, camera intrinsics,
  roster, default car and car-texture metadata only; no meshes/draws/textures.
- `cars/<slug>.geometry.json` — `kind: "e1-drive.car-chunk"`, `version: 1`,
  `geometryVersion: 6`, `chunk:{kind:"car", slug, levelSha256}`; the body record
  (mesh, UV0 base64, textures, carDraws, carParts, wheelGroups, carNodes,
  manifest pins) at the top level.
- `car-bodies.index.json` — `kind: "e1-drive.car-bodies-index"`, `version: 1`,
  `geometryVersion: 6`; `level`, `base`, `debug`, `packet`, `roster`,
  `defaultCar`, `cars[slug]` and a `policy` block (1 level + 2 car chunks
  resident, typed missing-chunk error, no streaming/eviction).

The index policy block is part of the contract:

```json
{
  "levelChunksLoaded": 1,
  "carChunksResident": 2,
  "carChunks": "the selected car is loaded on demand and cached; MP loads the remote car once",
  "missingChunk": "typed load error; never substitute another car body",
  "streaming": "none in this pass: one level + one/two cars resident"
}
```

## 2. Load flow

`web/geometry-chunks.js` is the DOM-free contract (browser + Node verifier).
`web/app.js` implements:

1. fetch and parse `car-bodies.index.json` once; validate kind/version/geometry
   version/roster/default car and every entry's SHA-256 shape;
2. fetch `level.geometry.json` (River) or the map package + `base.geometry.json`
   (Amboy/Gracia) once; verify bytes and SHA-256 against the index;
3. fetch the selected `cars/<slug>.geometry.json`; verify bytes and SHA-256,
   parse the car chunk and reject fallback bodies;
4. `assembleGeometry(levelDocument, carBody)` → the same v6 document with
   `carBodies = { [slug]: body }`; `createSession` builds the identical packet;
5. cache the level/base/car documents. A car switch preflights the next chunk,
   then rebuilds the engine/session in place (no page reload, no level fetch)
   and `history.replaceState` updates `?car=`;
6. MP: each player loads its own car; the room roster carries each player's car
   (the committed net-mvp state quantizer drops unknown snapshot fields, so the
   page uses the roster entry, not a new wire message). The peer's chunk is
   loaded once, uploaded as a second ghost-pipeline mesh and drawn with the
   peer's wheel rest matrices. A failed peer chunk is stored as
   `state.mp.remote.carChunk {status:"error", code, error}` and the remote car is
   not drawn.

Typed errors (`ChunkLoadError.code`): `CHUNK_INDEX_MISSING`,
`CHUNK_INDEX_SCHEMA`, `CHUNK_LEVEL_MISSING`, `CHUNK_LEVEL_SCHEMA`,
`CHUNK_LEVEL_SHA256`, `CHUNK_LEVEL_BYTES`, `CHUNK_BASE_*`, `CHUNK_CAR_MISSING`,
`CHUNK_CAR_UNKNOWN`, `CHUNK_CAR_SCHEMA`, `CHUNK_CAR_SHA256`,
`CHUNK_CAR_BYTES`. There is no substitute body and no silent same-car fallback.

### Caching / residency

- one level (or one map package + base) resident;
- selected car resident; a switched-to car replaces nothing but its own body
  (the level document is reused);
- MP peer car resident as a second car; AI cars continue to use the local body;
- no streaming, eviction or partial upload in this pass.

`verify_e1_drive.mjs` now:

- parses/pins the index, level, base and all 15 car chunks;
- proves every car chunk is byte-identical (metadata keys aside) to the combined
  debug body and that the level chunk is structurally identical to the combined
  level half;
- creates every per-car packet from `assembleGeometry(levelChunk, carChunk)`
  instead of the combined document, so the existing per-car packet hashes and
  the 2281+ checks are the invariance proof.

### Limits

- one level + one selected car (MP: + the peer body) resident; no streaming or
  eviction;
- texture RGBA still dominates the car chunks (2.38–5.0 MB per car); batch 2
  must stay within the declared budget by measuring the page load, not by
  compressing or dropping pixels;
- the remote car uses the existing diagnostic ghost tint and does not sample its
  own textures (the ghost shader samples none); this is a presentation limit, not
  a geometry fallback;
- the combined `geometry.json` remains on disk for the committed layout/ghost
  pins and the verifier; it must not be served to the page;
- map packages reuse the small base chunk; the map package itself is unchanged.
