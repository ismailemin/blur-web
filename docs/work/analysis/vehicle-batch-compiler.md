## 1. Spec format

`probes/vehicle-batch/spec/cars.json` (`kind: blur.vehicle-batch.spec`,
`version: 1`, 233,782 B) is the single config file. It is generated by
`probes/vehicle-batch/tools/spec_gen.py` from committed data; it is not
hand-edited and `--check` re-derives it byte-identically.

```jsonc
{
  "kind": "blur.vehicle-batch.spec",
  "version": 1,
  "sources": { "carsJson": {...}, "cAliases": {...}, "amaxJsonl": {...},
               "roster": {...}, "rootPak": {...}, "hud": {...} },
  "counts": { "records": 62, "classA": 5, "classB": 42, "classC": 15,
              "inRoster": 25, "remaining": 37, "withBody": 61, "withHud": 61,
              "wheelProofKnown": 21 },
  "cars": [ /* 62 entries */ ]
}
```

Every entry covers the fields the current pipeline needs:

| field | source | notes |
| --- | --- | --- |
| `slug`, `recordIndex`, `recordId`, `recordName` | `cars.json` | unique; `slug` drives the output dir |
| `class`, `classReason` | `cars.json` | V1 A/B/C classification |
| `scope`, `rosterPosition` | `probes/e1-drive/cars/roster.json` (read-only) | `roster` = already integrated |
| `drivetrain`, `massKg`, `gears` | `cars.json` | roster `layout` string |
| `physics.{fieldsPath,fieldsSha256,gatePass,driveType,wheelBase}` | `cars.json` | 62/62 gate pass |
| `body.{route,pakPath,logicalBytes,sha256,decodedPath,rule,prefixCandidates}` | `cars.json` (B/A) or `c-aliases.json` (C) | `route` = `exact` or `alias` |

| `alias.{amaxTag,amaxRecordId,amaxRefIndex,…}` | `c-aliases.json` | record-level identity, `nameSimilarityUsed:false` |

## 2. Compiler

`probes/vehicle-batch/build.py` orchestrates the proven builders; it reimplements
no decoding:

| step | proven code called |
| --- | --- |
| record → model evidence, pak decode, manifest/mesh/scene | `build_all_manifests.map_car` + `.extract` + `.build_manifest` (which runs `probes/car-parts/tools/build_manifest.py`) |
| materials + UV0 | `stage_batch3.material_pass` → `tools/inspect_car_materials.py` |
| wheel model decode | `stage_batch3.decode_wheel` → `tools/prepare_asset_fixture.decode_packet_zlib` |
| wheel scene / model | committed `scene_inspect.exe` / `model_inspect.exe` |
| HUD (spec generation) | `hud_catalog.py` parsers (`extract_gamedata`, `parse_loc`, `amax_hud`, `extract_root`, `parse_ipf_names`) |
| pak index | `tools/inspect_asset_layout.pak_index` |

### 2.1 Commands

```powershell
$py = "C:/Users/ismailemin/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe"

# spec (regenerate / verify no drift)
& $py probes/vehicle-batch/tools/spec_gen.py
& $py probes/vehicle-batch/tools/spec_gen.py --check

# plan: no writes, machine-readable plan
& $py probes/vehicle-batch/build.py --dry-run

# stage every record outside the 25-car roster
& $py probes/vehicle-batch/build.py

# one or more cars (slug or record index)
& $py probes/vehicle-batch/build.py --only bmw-m3e92-drift,73

# other scopes / forced rebuild
& $py probes/vehicle-batch/build.py --scope all
& $py probes/vehicle-batch/build.py --no-resume

# second independent build + gate
& $py probes/vehicle-batch/build.py --out-root _work/vehicle-batch/_repeat
& $py probes/vehicle-batch/verify.py
```

Options: `--scope {remaining,all,roster}` (default `remaining`), `--only`,
`--dry-run`, `--no-resume` (resume on by default), `--out-root`, `--cache`,
`--spec`. Exit code `0` = every selected car staged or blocked; `1` = a
`partial`/`error` record.

### 2.2 Resume

`<slug>/staged.json` stores the input identity (spec entry hash, body SHA-256,
body/wheel pak paths, SHA-256 of `build_manifest.py`, `inspect_car_materials.py`,
both reader executables) and every artifact hash. A car is skipped only when all
inputs and every artifact hash still match. On the recorded second run 32 cars
were `resumed` and 0 were rebuilt; changing the spec for `DefaultCar` re-ran only
that entry.

## 8. Limits

- **Staging only.** No roster, P52 committed material, car-texture, geometry,
  ghost, web, chunk or browser change is made. No car is claimed drivable.
- A `staged` record proves the body/wheel model, part manifest, LOD0 mesh, scene
  report, UV0 and the independent material traversal parse and agree. It does not
  prove runtime paint/light materials, high LODs, visibility, suspension,
  steering, camber or wheel corner identity.
- **Texture RGBA bytes are the independent traversal's bounded estimate**
  (`width × height × 4` at the highest populated LOD within the committed bound),
  not the P52 decode. P52 counts and pixels come from the main-agent steps.
- The staged `manifest.json` embeds the staging cache path in `source.model`;
  its hash is therefore **not** the committed hash. `mesh.json` and
  `scene-report.json` are path-independent and final.
- **Wheel corner identity** stays preview-paired where measured; no corner is
  guessed.
- The four builder rejections are reported, not worked around. `DefaultCar`
  remains unsupported.
- Ghost values, capture images and page-load measurements are main-agent work.
- The 62-car spec is derived from the V1/V3/V6 audit artifacts at the hashes
  listed in §1; if those inputs change, re-run `spec_gen.py --check`.
- No retail/full-game, renderer, driver or multiplayer claim is made.
