Blur Web input layer — manual controller check

This page is the documented manual check for the gamepad path. The automated verifier (node probes/input/verify_input.mjs) uses a synthetic Gamepad API stub; it is not hardware verification. A human with a physical controller must run this page and record what was observed.

Steps

  1. Connect an XInput-compatible pad before opening the page, then press a button once (the Gamepad API only exposes a pad after user activity).
  2. Check the pad line below: it must name the device, show standard mapping and connected.
  3. Press RT slowly: throttle must rise from 0 to 1 in steps (not 0/1). Press LT: brake must do the same.
  4. Move the left stick: steer must stay 0 near the centre (25% radial deadzone) and reach ±1 at the rim. The D-pad left/right must also steer.
  5. Config 0: B is the handbrake, A uses a pickup, RB fires changeViewPressed once per press. Config 1/2 change these; use the buttons below.
  6. Move the right stick: lookX/lookY must follow it. Hold Tab (layout 1: PageDown): rearView becomes true and lookY is forced to −1.
  7. Unplug the pad while holding RT: the pad line must switch to disconnected and every control must return to 0 on the next sample. Reconnect: nothing may remain stuck.
  8. Keyboard: layout 0 uses Q/A/arrow steering and ArrowDown handbrake; layout 1 uses W/S/A D and Space. Use the layout buttons below.
